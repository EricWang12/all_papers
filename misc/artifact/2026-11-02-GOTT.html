GOTT

GOTT: Object-centric Dexterous Manipulation with a Reusable Cross-Embodiment Primitive

Yulin Liu, Lai Wei, Yen-Jen Wang, Akash Sharma, Pieter Abbeel, Henrik I. Christensen, Haozhi Qi · Amazon FAR / UC San Diego / UChicago / UC Berkeley · arXiv 2610.03861, v2 2026-10-08

arXivPDF Project page

归档到 misc：按要求放进 misc。内容上最近的是 Sim-robot-learning（IsaacLab 里 RL 训跨手 primitive，sim-to-real），也和 Robotic-harness 相关：它定义的 reach spec + object trajectory 正是 harness 高层可以调用的底层接口。

TL;DR

Problem
Object trajectory 只说"物体怎么动"，不说"手在哪、怎么抓稳"。现有灵巧手方法要么把 grasp 开环执行（没反馈），要么把 contact 和任务/手型绑在一起学（不可复用）。
Idea
把执行拆成 reach → acquire → move：高层只需给一个大致的 reach specification（VLM affordance + future-aware IK、或人手 demo、或参考 grasp），中间一个跨手共享的闭环 contact-acquisition primitive（RL，局部 hand-object 观测，canonical 26-joint/21-link 表示）负责抓稳，然后 pose-conditioned tracker 按 FoundationPose 的物体位姿跟踪轨迹。
Result
仿真 lifting 9,588 个物体：unified policy 78.7%，CrossDex 51.7%，BODex 38.7%（Table 1）；零样本到没见过的 Allegro 变体 72.1%（Table 2）。真机 4 个任务 tSR 80.0%，开环 BODex/DRO 都是 35.0%（Table 3）；DexYCB 499 条人手 demo 零样本执行 69.7%，kinematic replay 12.6%。

Problem

知道钻头该怎么转，不等于知道手该怎么握住它

Running example · 后面每个 stage 都跟着它走

Drill Use（真机，Franka Research 3 + Sharpa Wave 22-DoF 左手）：输入是 drill 的 mesh（iPhone AR Code 扫的） + 期望的 object trajectory：把 drill 绕指定轴转 45° 到工作姿态 + 任务描述 "Drill Use"。桌上 drill 的位置随机 ±0.10 m、朝向 ±30°。想要：手握住 pistol grip（不是 chuck），抓稳后带着 drill 走完这条轨迹（Table 3 / Table 5 的 Drill Use）。

BODex/DRO 的"坏在哪"来自 §4.3 和 App. D 列的三种失败模式（Fig. 13）：抓到不支持任务的区域、接近时把物体推开、cage 式抓握。Drill Use 的 7/10、6/10 是 Table 3 的 tSR；CrossDex 的数字是 Table 1 unified 行；SimToolReal 数字来自 §4.4 / Fig. 8；replay 数字来自 §4.5.2。lane 4 的输入是人手视频里的 object trajectory，不是规划出来的。

  1. (a) drill、(b) mustard（BODex）：手接近时就把物体推倒或推走，开环的 grasp 还是按原位置闭合，落空。
  2. (c) brush（DRO）：手指围成一个笼子，拇指和其他手指没有相对的夹持力，一扫地刷子就从手里滑出。这就是 Trash Cleanup 上 DRO tSR 0/10 的原因（§4.3）。
  3. (d) eraser（DRO）：抓的区域不对，后面的擦板轨迹做不了。

根本问题：object trajectory 把"物体怎么动"和机器人解耦了，但"手在哪、怎么建立稳定接触"没有一个跟任务、轨迹、手型都无关的可复用模块。　这篇的切入点：把 contact acquisition 单独抠出来做成一个闭环 primitive，高层只需要给一个"差不多的"初始化，primitive 负责把它变成稳定接触。

Level 3 · Details

每个 stage 的细节

Stage 1 Plan reach spec（future-aware planning） mesh + τo + 任务描述 → ρ = (ξapp, ginit)
  • Why：几何上稳的 grasp 不一定能用（握 chuck 钻不了孔）；一开始够得着的手型，沿轨迹转到一半可能关节到极限或撞上（Fig. 3）。
  • How · VLM affordance：把物体按观测位姿渲染 4 个侧视图（带像素网格），prompt VLM 标出功能部件、选 holding region 而不是 working end、给 2–4 个点覆盖它的长度；各视图的点反投影到 mesh 上投票，取 3 cm 邻域作为 ℛ（App. B，prompt 原文在论文里）。
  • How · 候选：用 BODex 的轻量初始化阶段在 ℛ 内采 N = 10 个 gi，碰桌子的和病态的丢掉。它们只是"大致初始化"。
  • How · trajectory-aware 选择：每个 gi 用 cuRobo 规划无碰撞接近 ξapp；再假设 hand-object 相对变换固定、让物体沿 τo 走，沿途解 IK；接近不可行、IK 超限或不收敛的候选丢掉；剩下的选累计关节运动 Σ‖qt − qt−1‖ 最小的 g⋆。
  • 耗时：VLM 推理 14.9 s，IK filtering 3.95 s，cuRobo 9.6 s，一次性初始化约 29.6 s（Table 14）。

Stage 2 Reach ρ → 手停在物体附近，触发 acquire
  • Why：把"长距离、无碰撞、arm 相关"的运动和"局部、接触密集"的控制分开；reach 只负责前者。
  • How：机器人沿 ξapp 走向 ginit；感知端 SAM2 在第一帧分割目标，FoundationPose 用 mesh 做 6D 位姿跟踪（45 Hz，policy 10 Hz 取最新估计）；当手的 link 到物体表面最小距离小于 εapproach，控制权交给 primitive。
  • 来源无关：Source 2 的 ξapp 是 retarget 的人手接近段，终点不必是精确 grasp，同样在这一步结束时交给 primitive（§3.4）。

Stage 3 Acquire（contact-acquisition primitive） 大致初始化 + 局部观测 → 稳定接触，predictor 判定后切换
  • Why：这是整篇论文的核心模块：把上游任何来源的"差不多"初始化变成稳定抓握，补偿位姿误差、几何不匹配和接触不确定性。
  • 观测（Table 8）：不直接给物体位姿。三块：① 21 个 canonical link 各自到物体点云（512 点）最近点的位移向量（63 维，物体信息只从这里进来）；② 26 维 canonical 关节位置 + 上一步关节目标，最近 K = 5 帧；③ 21 个 link 的 3D 位置，5 帧；再加 joint mask（26）和 link mask（21）标明哪些槽位有效。
  • 动作：6 维 end-effector 增量（±0.008 m、±0.052 rad/步）+ 26 维 canonical 关节增量，mask 掉无效槽位后映射回本机关节顺序；10 Hz。网络是 MLP [512, 512, 256, 128]，每步 0.752 ms。
  • 什么时候算抓稳：单独训的 contact predictor（2 层 MLP 256，只看最近 5 步的本体感觉）输出 5 根手指的接触概率；拇指 + 至少一根其他手指连续 5 步超过 τc = 0.5 就切到 move。只用本体感觉是为了对物体位姿噪声免疫（Fig. 15：object pos 噪声到 5 cm 精度不变）。
  • 跨手：同一个 checkpoint 在 XHand（12-DoF）、Sharpa Wave（22-DoF）、Allegro（16-DoF）上都能跑，靠的是 canonical 表示，见 stage-all。

Stage 4 Move（pose-conditioned end-effector tracking） 稳定接触 + τo → 物体沿轨迹运动
  • Why：抓稳之后就不需要 RL 了：把 hand-object 相对变换当作固定，跟踪就是一个 IK / 位姿控制问题，也因此和 arm 无关。
  • How：先短暂抬起；每步由期望物体位姿 TO,t 和估计的 hand-object 变换算出 end-effector 目标，用 FoundationPose 观测到的物体位姿误差修正，再交给低层位置控制器。
  • 代价：假设握住后物体不在手里动，所以做不了 in-hand 操作（§5）。

贯穿 Stage 3 Primitive 的训练和 canonical 表示（为什么一个 policy 能跨手） 16 个 YCB 物体 × 三只手 → 一个 checkpoint，零样本到真机和没见过的手
  1. (A) RL Environment：四只手（XHand、Sharpa、Allegro 和另一只）围着一个 drill，每个 episode 从一个随机的 Initial Configuration 开始（BODex 为每个物体-姿态对生成 4,000 个），policy 只拿 Local Hand-Object 观测，目标是抓稳并抬起。
  2. (B) Unified Observation Space：每只手映射到 21 个 keypoint（1 掌 + 5 指 × 4）的网格；紫色 = 本机有的 link，灰色 = 没有的槽位，用最近的已有 link 填充，另加 mask 标记。
  3. (B) Unified Policy → Decode with Joint Masking：policy 输出 26 维 canonical 关节增量（拇指 6 槽，其余每指 5 槽），按每只手的 index map 和符号向量取出它有的关节，其余 mask 掉。
  • Canonical 槽位（Table 7）：Allegro 用 16 槽、Sharpa Wave 22 槽、XHand 12 槽。不需要每只手单独的 encoder/decoder。
  • 奖励（App. A.1，Table 6）：r = 16·rdist + 4·rcontact + 1·rlift + 10·robj。rdist 是各 link 到物体表面距离的加权负和（拇指尖权重 8，其他指尖 4，掌 0）；rcontact = 拇指接触 + "拇指且至少一指接触"；rlift 只在抓住时奖励抬高（上限 5 cm）；robj 惩罚物体在抓取过程中平移或旋转，权重从 2 退火到 10。
  • 训练：IsaacLab + PPO，4,096 并行环境，episode 60 步（6 s），2,000 epoch ≈ 4.915 亿步，单张 L40S 24 小时。域随机化：物体质量 ×[0.5, 3.0]、摩擦 [0.5, 1.5]、执行器刚度 ×[0.5, 2.0]，握住后施加 2 N 随机推力。
  • Contact predictor：policy 收敛后冻结，用它的 rollout 单独训（接触力 ≥ 0.05 N 为正样本）；单 episode 切换准确率 0.953–0.960，延迟中位数不超过 1 步。
  • 哪些设计真的重要（Table 4）：去掉 rcontact 成功率 0.0%、去掉 rlift 1.5%；去掉 link 位置观测 61.0%；本体感觉历史只留 1 帧 63.0%（掉 15.7 点）；换成 OHRA 式点云表示 25.7%。rdist 在训练手上只差 2.7 点（76.0 vs 78.7），但去掉它在没见过的 Allegro 变体上从 72.1% 掉到 55.1%，Fig. 6 显示它抑制了手指反折。

Results

结果一览

  • 78.7% 仿真 lifting（9,588 个 DexGraspNet 物体、54,149 个实例，只用 16 个 YCB 物体训练），三手 unified policy；CrossDex unified 51.7%，BODex 38.7%，DRO 40.5%（Table 1）。联合训练比各手单独训（75.4%）还高。
  • 72.1% 零样本到三个去掉手指 link 的 Allegro 变体，和逐变体训的 oracle 72.2% 持平；只在原 Allegro 上训的 policy 只有 17.2%（Table 2）。跨手能力来自多形态联合训练，不只是 canonical 表示。
  • 90% / 90% / 96% 真机抓取（10 个物体 × 5 次），Franka-Sharpa / Franka-XHand / Tianji-XHand，同一个 checkpoint（§4.1.2，Table 11）。
  • 80.0% tSR 真机 4 任务平均（10 次/任务），gSR 87.5%；BODex 和 DRO 都是 tSR 35.0%、gSR 57.5%，其余模块（感知、VLM、IK 选择、跟踪）完全相同（Table 3）。
  • 0.914 vs 0.002 SimToolReal 的 eraser 任务，桌面低于其假设高度 0.4 m 以上时；在它的训练高度附近 SimToolReal 0.983、GOTT 0.792（Fig. 8，600 个 episode）。
  • 69.7% DexYCB 499 条人手 demo 零样本执行（MuJoCo；IsaacLab 71.5%，ManiSkill 72.9%），kinematic replay 12.6%；SPIDER 76.0% 但要逐 demo 做物理优化（§4.5.2）。
  • 65% tSR Drill Use 20 场景的 affordance + future-aware 选择（claude-opus-4-7），随机 20%、仅 IK 30%；VLM 之间 50–65%（Table 5）。

baseline 数字低于原论文的原因（App. E）：GOTT 的协议把物体从一开始就放在有重力的桌面上、要求抬起 5 cm 并稳住，BODex 原协议是悬空施力；同一批 BODex grasp 在两种协议下成功率相近（Fig. 14），所以差距不是协议造成的。

Limits

局限和开放问题

  • 高层规划和 contact acquisition 是串行的：reach spec 选得差，primitive 没法回头改（§5）。
  • 跟踪完全靠视觉位姿估计，手把物体挡严实时 FoundationPose 会失效；作者提触觉或 visuotactile 估计是下一步（§5）。
  • 抓住后 hand-object 变换当作固定，所以做不了拧盖这种 in-hand 操作（§5）。
  • 一次性初始化约 30 s，其中 VLM 推理 14.9 s（Table 14）；VLM 选区域的 func. 在不同模型间 65–85%（Table 5）。
  • εapproach 的数值、真机上的 reach 失败率论文没有单独报告；代码写的是 Coming Soon。

For misc（最近的项目：Robotic-harness 和 Sim-robot-learning）

对我们有什么用

  • Robotic-harness：reach-acquire-move 正是 harness 想要的底层接口：高层（LLM/VLM 或 code-as-policy）只需输出 object trajectory + 一个大致的 reach，不用输出精确 grasp。App. B 的 VLM keypoint prompt（4 视图、holding region vs working end、JSON 输出）可以直接做成 harness 里的一个 tool，Table 5 给了它的可靠度。
  • Agent-centric real-to-sim：Source 2/3 用 FoundationPose 从人手视频抽 object trajectory 再交给 primitive，和 real2sim-anything 的 video → sim 流程接得上；primitive 在 IsaacLab 训、零样本进 ManiSkill / MuJoCo（69.7–72.9%），说明这类局部接触 policy 对仿真器不敏感，进 Genesis 也有希望。
  • Sim-robot-learning：一份可复用的跨手训练配方：canonical 26-joint / 21-link 表示 + mask、只给 link-to-object 向量不给物体位姿、rdist 当形态正则、policy 收敛后单独训本体感觉 contact predictor。单张 L40S 24 小时。
