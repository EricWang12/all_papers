TL;DR

谁做的
苏度科技（上海）/ Sudo AI GmbH（瑞士），核心就是原 Hillbot 班底：苏昊（Hao Su，SAPIEN、ManiSkill 的作者）、CEO 韩铮、COO Martina Hansen。sudo.ai 这个域名 2023–2025 年挂的是他们的 3D 生成 app sudoAI 报道 论文
是什么
一台自研的双臂上身机器人，加一个只做 pick 的 policy。官方说完全用仿真数据训练、零真机数据，首抓成功率约 98%，两次内接近 100% 官方。7 月以后的采访改口：最后 1% 要靠真机数据微调 报道
谁定目标
演示平板上有 Pick Specified Object Demo 模式：人在胸口相机画面上点一下目标 视频。点击 → 分割出 target mask → 每帧跟踪，mask 和图像一起喂给 policy 推测·中。点击也能换成 VLM 指物，UI 里有 Reasoning 面板 推测·中
Policy 吃什么
胸口双目 + 手腕三目，都是被动双目，没有投射器 视频；sudo 的招聘写着机器人数据里有 图像与深度流，要质检 深度-彩色对齐 招聘。所以 policy 多半吃双目算出、和彩色对齐的 RGB-D（多半转成点云），加 target mask 和关节状态 推测·中。每步只出一个动作，15–25 Hz，不做 action chunking 官方。CEO 说仿真里渲染的“分辨率其实非常非常低”，部署时“是一个端到端的模型” 报道
怎么训
在 SAPIEN/ManiSkill 里大规模生成场景 招聘；看得到真值的 expert（沿标注好的 grasp pose 做 motion planning，或用 state 训的 RL）出动作，再蒸馏成只看相机的 student，DAgger 式 推测·高；视觉随机化、传感器仿真、延迟和频率随机化补 sim2real 官方 推测·中

Running example · 后面每节都跟着它

桌上几个透明玻璃瓶。操作员在平板的胸口相机画面上点中间那只 → 机器人去抓 → 抓到一半，有人把瓶子挪开 → 它追过去重新抓起。

这个例子是把官方两段片段拼起来的：“透明物体”片段（开头露出平板 UI）和“干扰”片段。

  1. 两个模式：Pick Specified Object Demo（选中）和 Sorting Workflow Demo。前者就是你看到的“点一下再抓”。分拣要高层决定哪件放哪，所以才有 ⑥ 视频 推测·中
  2. chest_left_camera：胸口 stereo 的左目。上面叠的绿色四边形四角有圆点，像一块能拖动的工作区（只在这块桌面里找目标） 推测·中
  3. left_hand_left_camera：左手相机的左目，所以手腕上也是 stereo 视频
  4. Detection 标签页（另外两个标签太糊，读不出）：有一步显式的检测/分割结果给人看，支持“点击 → mask” 推测·中
  5. 状态条 Picking up object：pick 外面包着一个任务状态机（选目标 → 抓取 → 放下 …） 推测·中
  6. Reasoning 面板（截图时为空）：给 VLM/LLM 写推理过程的地方，点击之外的第二个“选目标”入口 推测·中
  7. 红色按钮：大概是停止 推测·低

实线是我认为每帧都在跑的部分；虚线是可替换的目标来源。整张图都是 推测·中，依据是 UI 上的标签和官方“每步都看最新观测”。

  • 为什么要人点：把“抓哪个”这个语义问题交给人或 VLM，policy 只学一件事：把 mask 盖住的那个东西抓起来。仿真里 mask 的真值不要钱，真机上 mask 是二值图，没有颜色和纹理的 sim2real gap 推测·高
  • 公开展会大多不用点：官方 LinkedIn 写 Bring an item and test it yourself!，PingWest 写观众把物品放到机器人面前，机器人会自己选择一个可以下手的局部区域 官方 报道。可见有两种模式：自动挑目标，和你看到的“人来指定” 推测·高
  • 60 分钟评测没人点：官方标的是 “fully autonomous”。我在 60 分钟里抽看了 16 帧，只有人路过或复位物体，没人碰平板。那时目标多半由程序自动挑，比如工作区里任选一个检测到的物体 推测·中
  • 点到一半物体被挪走：mask 由跟踪器每帧更新，policy 每帧重新看，所以能追（下文 “行为 ↔ 机制”）

Localization · 三件不同的事

“定位”在这套系统里分三层，只有第一层在 policy 里

目标在哪

object localization · 在 policy 里

  • 点击只给一个像素 (u, v)；分割把它扩成整块 mask；跟踪让 mask 跟着物体和相机走 推测·中
  • 不一定算 3D 坐标。闭环 policy 像 visual servoing：每步看“指尖和目标在图里差多少”再修一点，误差每步都被重新测，标定误差不会累积 推测·高
  • 要 3D 的地方（绕障、够不够得着），用胸口和手腕双目算出的深度（见 深度和点云去哪了） 推测·中

相机在哪

extrinsics · 出厂固定

  • 相机都长在机器人身上：胸口相机相对底座固定，手腕相机跟着正运动学走，出厂标一次即可 推测·高
  • 有聚合站转述 sudo “不需要 calibration”。更可能指部署现场不做 hand-eye 标定：训练时把相机内外参随机抖几毫米、几度，policy 就不在乎安装误差 推测·中
  • 先例：ManiSkill3 的 sim2real 每步把相机抖 2.5 cm；GraspVLA 在 15 cm 的球内、±5° 随机外参；Sadeghi et al. 2017 的 recurrent policy 换视角后能“隐式自标定” 论文

机器人在哪

robot localization · 不在 R1 里

  • R1 演示是固定底座，用不到这一层
  • 招聘里的 VSLAM（单目/双目/RGB-D VI-SLAM，ORB-SLAM、VINS 一系，加 3DGS-SLAM）和自研导航栈（定位、建图、规划、避障），是给超市这类移动场景的 招聘
  • 两者分工：导航把底盘停到货架前，pick policy 只管相机里看到的那一块 推测·中

点击是怎么“插进”网络的：三种做法

A · mask 当第 4 通道

RGB-M，每帧由跟踪器更新

  • 仿真：渲染器直接给目标的真值分割
  • 真机：点击 → SAM 类分割 → 视频跟踪（SAM 2 一类）
  • 物体被挪走，mask 跟着走，policy 自然追过去
  • 代价：每帧多跑一次跟踪。不算瓶颈：SAM 2.1 tiny 在 A100 上 91.2 FPS，Cutie 约 45 FPS 论文
  • 公开样板：DexGraspVLA（框 → SAM → Cutie 每步跟踪 → mask 变 token）；ManipGen（首帧 + 目标 mask 当额外通道） 论文

我最看好：和 Detection 标签、追移动目标都对得上

B · 点击坐标当 token

只在第一帧给 (u, v)，网络自己记

  • 不用外部跟踪器，最省算力
  • 网络要自己完成“认出是哪个 + 一直记住”
  • 被手挡住、被人挪走以后容易认错

把握低：和 UI 里显式的 Detection 不太搭

C · 反投影成 3D 目标点

stereo 深度把点击变成 (x, y, z)

  • 当 goal 向量给 policy，最像传统 goal-conditioned RL
  • 物体一动就要重新检测，否则追的是旧位置
  • 透明物体深度不准，点会偏

把握低到中：可能作为 A 的辅助输入

深度和点云去哪了：三种可能

改过的排序：B > A ≫ C 推测·中。上一版是 A > B，因为我把手腕看成了普通相机；其实被动双目就是深度相机。输入里一定有 RGB：显示屏桌面测试只对看 RGB 的 policy 有意义；官方也说视觉随机化让 policy rely on the geometric and physical cues relevant to grasping 官方。所以 B 是 RGB-D，不是只有深度。

做法透明玻璃上支持反对
B · 双目先算深度，和彩色对齐成 RGB-D（你的猜测）
learned stereo 出深度 → 点云（每点带颜色和目标标志）进 PointNet 类编码器，或每路一张 2.5D 图		stereo 网络用仿真里的透明物体训过，玻璃上也能出深度：SimNet 抓透明这类难物体 95%，RGB-D baseline 35% 论文手腕、胸口都是被动双目；招聘里有深度流和 深度-彩色对齐 招聘；苏昊组的老路：PointNet、ManiSkill 的点云观测、DexPoint、3D 点云 RL；T-RO'23 的手腕深度 student 真机 96.25%多一个网络、一份延迟；仿真里要渲染左右图、跑同一个 stereo 网络，深度的瑕疵才和真机一致。但只有蒸馏 student 时才渲染（teacher 读真值），规模小得多
A · 图像进，3D 在网络里
多目 RGB + mask 直接进网络，网络自己学视差；训练时让辅助头回归目标 3D 位置、深度		玻璃的像素一直在图里，网络从轮廓、折射、高光里学几何CEO 的“隐式表达”和“端到端”；官网说 3D 避障是 integrated learned behavior；DextrAH-RGB（真机 stereo 77%，单目 73%）、GraspVLA（只用 RGB，透明物体 86.6%，AnyGrasp 10%）都这么做 论文硬件能出深度、数据里也存深度，不用而让网络自己学，需要一个理由；从图像学深度最吃数据
C · 传统 stereo 匹配出深度 → 点云
SGM 一类算法，或相机自带的深度芯片		玻璃上出洞、错位；T-RO'23 要专门模拟这种失效最省事；ManipGen、T-RO'23 都用手腕深度相机透明瓶是招牌演示；三根线把原图送进主机，看不出有自带深度芯片 推测·低
  • CEO 原话：在仿真器里，机器人要知道物体的几何位置，预估材质和重量，分清瓶盖和瓶身，操作时往哪个方向转——这些都是有理解和推断的，可以用隐式表达来描述 报道
  • 这就是 teacher-student 的老套路：teacher 直接读这些真值，student 只看图，被逼着把它们编进隐变量。RMA 的 student 估的就是质量、摩擦这类隐变量 论文 推测·中
  • B 和 A 的边界很细：把 stereo 网络的中间特征而不是深度图交给 policy，B 就滑成了 A；区别只在中间有没有一张显式的深度图 推测·中
  • 分割：目标 mask 几乎肯定给。仿真里用真值 mask，训练时故意腐蚀、膨胀、偶尔丢几帧，模拟真机上分割和跟踪出错 推测·中。全场景分割多半不给：真机上每帧都跑又慢又不稳，正是 sim2real 最容易出问题的地方 推测·中

为什么不做 action chunking

  • Chunking 是看一次、执行 N 步再看。官方的例子：20 Hz with 20-step chunks effectively observes the environment only once per second 官方
  • 单步就是每 40–67 ms 都重新看一次，所以能追移动的瓶子、被推开后马上修正
  • 单步 policy 也正好配 DAgger 或 RL：expert 在任何状态都能给出“此刻该怎么动”的标签，不需要整段轨迹 推测·高
  • Chunking 主要帮的是模仿人类示范：ACT 里 chunk 从 1 加到 100，成功率 1% → 44%。π0 的 50 步块开环执行，每 0.5–0.8 s 才推理一次 论文。expert 是算法时，同一状态的标签前后一致，单步就够；DextrAH 系和 ManipGen 的单步 student 都跑 60 Hz 论文 推测·中
  • “15–25 Hz，随情况自适应”：可能是推理耗时随场景变（几路 mask、多少物体）。训练时随机化控制周期，policy 就不依赖固定频率 推测·低

  1. 资产工厂 各种来源的 3D 模型 → 能直接进仿真的资产
    • 外部供应商资产、真实扫描重建，加 图生 3D 资产管线 批量补类别 招聘
    • 每个资产标 geometry、collision、joint、material、physical properties、grasp pose，并有“视觉 + 物理保真”的验收 招聘
    • 图生 3D 是他们的老本行：Zero123++、One-2-3-45++（单图 → 带贴图网格约 1 分钟）挂在 SUDO-AI-3D 的 GitHub 下，MeshFormer 的署名里有 Hillbot 论文
    • 没见过的玻璃瓶也能抓，主要靠这一层的覆盖面：同类形状和材质在训练里见过足够多 推测·高。Tobin et al. 2017 只用几百万个随机程序生成的物体训练，真机抓取 80% 论文
  2. 场景生成 资产库 → 成千上万个可解的抓取场景
    • 场景采样、机器人初始状态与物体位姿生成、任务约束、可解性验证、corner case 挖掘 招聘
    • 可解性验证 = 只保留存在无碰撞可达 grasp 的场景；障碍物密集、目标半遮挡的场景故意多放 推测·中
    • 在同一步里把桌面贴图、背景、光照、相机参数、机器人外观一起随机（见下表）
  3. Privileged expert 真值状态 → 每一步的“正确动作”
    • expert 直接读仿真里的物体位姿、几何、标注好的 grasp pose，不需要看图 推测·高
    • 两条路招聘里都有：motion planning 沿 grasp pose 生成无碰撞轨迹（避障天然包含）；或者 PPO 之类的 state-based RL，查询便宜、被打扰后会自己纠正 招聘 推测·中
    • 先例：GraspVLA、MolmoBot 用规划器（cuRobo 等）离线生成上百万条演示；DextrAH-G 用读物体真值位姿的 PPO teacher；Hao Su 组 T-RO'23 用 SAC teacher 论文
    • RL 是主线的旁证：投资方稿件写的是 世界模型与强化学习一体化设计；TD-MPC 的作者里也有苏昊 报道
    • 例子里：expert 知道中间那只瓶子的真实位姿，瓶子被挪走的那一帧就给出“转向新位置”的动作
  4. 蒸馏成视觉 student 渲染的 RGB + 真值 mask + 关节 → 单步动作
    • student 只能看到真机上也有的东西：几路相机图和双目深度、目标 mask、关节状态 推测·高
    • 除了模仿动作，再加辅助 loss：让 student 从观测里回归目标位姿等真值。DextrAH-RGB 的 loss 就是动作 KL + 物体位置辅助 loss 论文；CEO 说的 隐式表达 多半就是这一类 推测·中
    • DAgger：让 student 自己开车，expert 在 student 走到的每个状态上标正确动作；student 因此见过自己犯错后的状态，学会恢复 推测·高
    • 训练时故意在抓取中途挪动目标、推一下物体，制造“被打扰”的状态 推测·中
    • 公开样板：DextrAH-G/RGB 正是“PPO teacher → 在线 DAgger → 单步 LSTM student”，RGB student 在 4×L40S 上训了 53 h 论文
    • 另一种可能：直接在像素上做 RL，critic 看真值、actor 看图（asymmetric actor-critic）；ManiSkill3 带渲染能跑到 30,000+ FPS，它的 sim2real 例子就是像素上直接 PPO 论文 推测·低
  5. 闭环评测 新 student → 在仿真 benchmark 上的成功率
    • 从强化学习的训练配置导入生成评测环境，再另做多样化评测集；设计失败判定 招聘
    • 测试经理一职写着 仿真用于筛选、真机用于确认 招聘
  6. 挖失败、再生成 失败案例 → 新的场景分布 → 回到第 2 步
    • 根据模型表现持续发现失败模式、生成新的训练分布和高价值数据 招聘
    • 官方说的 “a fundamentally different scaling curve” 就是这个循环：加数据靠算力，不靠人 官方
  7. （7 月以后）真机数据补最后 1% 仿真预训练好的 policy → 少量真机数据微调
    • 量子位 7 月报道：这1%的鸿沟…必须补上真机数据的微调；PingWest 列出的数据源还有遥操作、UMI、第一视角视频 报道
    • 和招聘对得上：UMI/DexUMI 无本体数采、VLA 后训练与持续学习 招聘。4 月发布的 R1 本身仍说零真机数据 官方
  • 每个场景渲染两路：胸口 + 手腕，和真机 UI 的两路相机对应 视频
  • 软阴影、金属碗的反光、锅铲边缘的少量噪点，像低采样光线追踪加降噪；SAPIEN 自带光追渲染 推测·中
  • 仿真里夹爪是绿色、手腕模组是深灰，真机是白色：机器人外观也在随机 推测·中
  • 场景是家居（棋盘地砖、柜子、台灯），比演示桌面宽得多：训练分布远大于测试场景 视频

和我们三条线的关系

  • Robotic harness：sudo 的切分正是 harness 的接口，“抓哪个”交给人或 VLM，“怎么抓”交给一个可靠的 pick(target_mask) 技能。他们还在招 具身智能体 Tech Lead，写着 Agent SDK、tool schema、MCP，要在这个技能层上搭 agent。
  • Agent-centric real-to-sim：他们的资产管线（图生 3D、重建资产、“视觉 + 物理保真”验收）和 三维视觉与虚实融合 岗位，和 WorldClaw 是同一个问题；区别是他们要的是一整个训练分布，不是一个数字孪生。
  • Sim robot learning：可以在 ManiSkill3 里复现一个最小版：state-based PPO teacher → 带 target mask 的 RGB student（DAgger）→ 低成本机械臂 zero-shot，验证上面哪些推测站得住。

还不确定的，以及去展位能直接问的

98% 该怎么读：公开的零真机结果，在宽物体集上大多是 74–93%（DextrAH、GraspVLA）；95–100% 的都来自小物体集（T-RO'23 的 8 个物体，SimNet）。R1 的 98% 更可能来自平行夹爪 + 桌面这种较窄的设定，加上大得多的规模，而不是一个全新的机制 推测·中。官方也没公布评测用了哪些物体、各多少次。
