TL;DR

Problem
学出来的机器人动作慢，原因分散在五环：示范采得慢、策略照着慢、推理和换段卡、一段内部不反应、任务本身太快。
Trend
最挤的是第 3 环：RTC 之后的后续和变体查到约二十篇，这里只收 6 篇。和 Flash ALOHA 同一路数（握臂示教 + 去掉手）的最近一篇是 HALO。
Caveat
“高频”多数指底层控制器（500 Hz–1 kHz）。学出来的那一环通常只有 10–60 Hz；声明超过 100 Hz 的，在查过的约 70 篇里只有 T-WLA 和 Tube Diffusion Policy。

#1HALO2026 下半年

HALO: Human-Aligned Data Collection for WhoLe-body MObile Manipulation

2026-11-12 · arXiv · HKUST / Robbyant

解决
移动操作的示范又慢又别扭：leader-follower 把人的手和视线同机器人的末端隔开，VR 又没有力反馈。
做法
人直接握着机器人的两只末端，推着一个被动小车走（代替底盘）；训练前把人的手分割出来、用 inpainting 补掉；策略是 π0.5。
快在哪
采集比 Mobile ALOHA 快到 2.9×（abstract）；一小时数据训出的策略 Disassemble Lego 75.0%，同样时间的 Mobile ALOHA / VR 数据训不出来。

PaperProject

这里的“快”是采集快，不是机器人动得快；没有报告执行速度。

#11PAKT2026 下半年

PAKT: Physically-Aligned Kinesthetic Teaching for Reinforcement Learning

2026-09-22 · CoRL 2026 · NVIDIA

解决
人用手带机器人时，会做出策略和控制器复现不了的速度、加速度和 jerk，这些示范落在学习器能执行的范围之外。
做法
人的推力先过 admittance controller，再过和策略动作同一个 reference generator（限速度、加速度、jerk）和阻抗控制器；存下来的是限过的动作。接进 HIL-SERL。
快在哪
策略 10 Hz，控制器 1000 Hz；cycle time 比 HIL-SERL 少 23%–48%（abstract），例如 peg 3.88 s → 2.17 s（Table 3）。

PaperProject

作者自己说：cycle time 的下降主要来自控制器栈，不是握臂接口。是 RL，不是纯模仿。

#15MEVION2026 下半年

MEVION: Low-Cost Open-Source Data Collection System for Powerful and High-Speed Dual-Arm Manipulation

2026-07-20 · IEEE Robotics and Automation Practice · 东京大学 JSK Lab

解决
ALOHA 是默认的开源 leader-follower 平台，但小舵机出不了大力和高速，重物和快动作示范不了。
做法
四只 6-DoF 臂，零件来自电商和钣金；肘部电机挪到靠近基座，用平行连杆驱动肘关节，减轻远端质量。
快在哪
最大关节速度 20.4 rad/s，ALOHA 是 3.1；最大力矩 60 Nm 对 21.2 Nm（Table I）。每只臂约 3,500 美元。

PaperProjectCode

快的任务（颠锅、达摩落）只在遥操作下展示；学出来的任务没有成功率数字。

#23I2RLC

Refinement of Accelerated Demonstrations via Incremental Iterative Reference Learning Control for Fast Contact-Rich Imitation Learning

2026-04-18 · arXiv（投 IROS 2026） · OMRON SINIC X / 筑波大学 / 早稻田大学

解决
人没法高速示范接触多的任务；直接把示范放快，接触动力学就变了，跟踪误差大甚至触发保护停机。
做法
先用 bilateral leader-follower 慢慢采；降采样得到更快的参考；在真机上回放，按跟踪误差迭代修正参考，一级一级提速。修好的快轨迹当训练数据。
快在哪
示范最多加速到 10×（abstract）；用 10× 数据训的 ACT 在 peg-in-hole 上 100%（Table V）。柔顺控制 500 Hz。

Paper

#26ExtremControl

ExtremControl: Low-Latency Humanoid Teleoperation with Scaled Velocity Feedforward

2026-02-11 · arXiv · UMass Amherst / CMU

解决
人形机器人遥操作的端到端延迟约 200 ms，差不多是人的一次反应时间，采不了需要反应的动态示范。
做法
在底层 PD 上加一项按比例的速度前馈；直接跟踪 6 个 link 的 SE(3) 位姿，用闭式的 Cartesian 映射代替环里的 retargeting。
快在哪
端到端延迟 54 ms（mocap）/ 64 ms（VR），已有系统约 178–454 ms（Table 1）。延迟从 50 ms 加到 200 ms，乒乓球回球率 80% → 20%（Table 4）。

PaperProject

只做到遥操作，没有用这些数据训练策略。

#30Tool-as-Interface2025 landmark

Tool-as-Interface: Learning Robot Policies from Observing Human Tool Use

2025-04-06 · CoRL 2025 · UIUC / UT Austin / Columbia

解决
遥操作慢、怕延迟，不适合动态任务；手持夹爪在惯性下工具会滑。快的用工具技能没法通过机器人来示范。
做法
人直接徒手用工具，两台 RGB 相机拍；训练时遮掉手、部署时遮掉机器人；动作是工具在任务坐标系里的位姿，换一只臂也能用。
快在哪
颠锅翻鸡蛋 1.5 s、12/12；同样的任务用遥操作数据训的 diffusion policy “Not Feasible”（Table 1）。

PaperProject

#32UMI窗口外 · 参照

Universal Manipulation Interface: In-The-Wild Robot Teaching Without In-The-Wild Robots

2024-02-15 · RSS 2024 · Stanford / Columbia / TRI

解决
遥操作慢，还离不开机器人；更早的手持夹爪位姿跟踪差，只能做准静态动作。
做法
手持夹爪 + 一台 GoPro，位姿来自 visual-inertial SLAM；策略接口在推理时对齐观测和动作的延迟，动作用相对轨迹。
快在哪
抛物入筐：对齐延迟 87.5%，不对齐 57.5%；示范速度是人手的 64%（Sec. V-B，Fig. 11）。

PaperProjectCode

2024 年 2 月，在时间窗口之外；只作为这一环的参照留下。

#4Learned Speed Prior2026 下半年

Retiming Robot Demonstrations with a Learned Speed Prior

2026-10-23 · arXiv · 首尔大学

解决
示范的节奏是遥操作员定的，不是任务定的；策略把操作员的慢也一起学走了。
做法
用遥操作数据和手持夹爪数据训一个 speed prior；让它按“手持”的节奏重读慢轨迹，得到新的时间表来重定时示范。底层用 1 kHz 力矩控制器跟踪。
快在哪
叠三个杯子 3.50 s，原节奏的策略 6.02 s，都是 29/30（Table 2）。策略 15 Hz，执行器 1 kHz。

PaperProject

#8AdaTempo2026 下半年

AdaTempo: Learning Shared Relative Tempo from Demonstrations for Faster Robot Manipulation

2026-10-02 · arXiv · 清华大学 / 复旦大学

解决
整体统一加速不可靠：任务的不同阶段能承受的加速不一样。
做法
用 DTW 把同一任务的示范对齐到统一的相位，取各条示范相对节奏的共识，得到连续的加速曲线，再重采样示范。训练和部署都不改。
快在哪
真机 ALOHA + ACT 六个任务平均快 2.02×，成功率 77.8%（ACT 58.3%，DemoSpeedup 56.7%）；Conveyor Fast 29/30、3.2 s（Table III）。

#16B-spline Policy2026 下半年

B-spline Policy: Accelerating Manipulation Policies via B-spline Action Representations

2026-07-10 · arXiv · Harvard / MIT / UT Austin

解决
离散的 action chunk 时间分辨率固定，段和段之间有跳变，一放快就跟不上。
做法
策略输出一段三次 B-spline 的节点和控制点；执行时密集采样、按倍数缩放时间，再把新的一段对齐到上一个已执行的动作。
快在哪
策略 10 Hz，spline 按 100 Hz 采样；Table Cleaning 开到 4× 用 11.80 s，同样 4× 的 chunk 基线 23.57 s（Table 1）。

PaperProjectCode

双臂 Speed Stacking 开到 4× 是 0/20：便宜的臂跟不上（作者写的局限）。

#21RL Token

RL Token: Bootstrapping Online RL with Vision-Language-Action Models

2026-04-24 · arXiv · Physical Intelligence

解决
VLA 在精细任务的“最后一毫米”又慢又犹豫；对整个模型做 RL 又太费真机数据。
做法
让 π0.6 多输出一个紧凑的 RL token 后冻结；在这个 token 上在线训练一个小的 actor-critic，输出对 VLA 动作段的修正。
快在哪
50 Hz 控制；插网线、插充电器的关键阶段约 快 3 倍，一半的 RL episode 比所有遥操作示范都快（Sec. VI，Fig. 9）。

PaperProject

吞吐量的具体数值只在图里，这里没有摘。

#24RACE

Time Optimal Execution of Action Chunk Policies Beyond Demonstration Speed

2026（ICLR） · ICLR 2026 · 首尔大学 / Vital Robotics / KAIST

解决
把 chunk 放快会改变控制器的动力学，还会撞上力矩和速度上限；异步推理又让前后两段对不齐。
做法
策略预测“到达的状态”而不是指令；用 TOPP-RA 在力矩和速度约束下做时间最优的重定时；测试时采样多段，挑最容易接上的一段。
快在哪
真机高精度任务比原策略快到 4×（abstract）；π0.5 传送带抓取 0.63 成功、9.8 s，15 Hz 原策略 0.03、21.3 s（Fig. 8）。

PaperProject

首次公开的日期没核实（OpenReview 拦了自动访问），按 ICLR 2026 记，时间轴上的位置是近似的。

#25Realtime-VLA V2

Realtime-VLA V2: Learning to Run VLAs Fast, Smooth, and Accurate

2026-03-27 · 技术报告 · Dexmal

解决
推理已经够快以后，VLA 驱动的轻型臂在精细任务上到底能跑多快。
做法
不动 VLA，只做部署栈：标定并补偿相机、本体、运动三种延迟；速度模型给每一步定快慢（用人实时“踩油门”的数据训）；QP 重排时间，MPC 跟踪。
快在哪
叠衬衫：遥操作示范 75.3 s，VLA 执行 18.9 s，人徒手 19.0 s（Figure 1）。

PaperProjectCode

技术报告，没有成功率表。

#27SAIL2025 landmark

SAIL: Faster-than-Demonstration Execution of Imitation Learning Policies

2025-06-13 · CoRL 2025 · Georgia Tech

解决
第一次把“比示范更快地执行”当成一个问题提出来：步长缩短以后，分布偏移、跟踪和延迟都会出事。
做法
四件套：段间一致性引导；预测到达位姿 + 高增益控制器；关键动作处自动放慢；按延迟丢掉过期的动作。
快在哪
仿真最多 4×，真机最多 3.2×（abstract）。Franka 上动作按 100 Hz 调度，力矩 500 Hz。

PaperProjectCode

#2CAC + Async ACT2026 下半年

Control-Aware Command Generation for Asynchronous Control and Action Inference with Vision-Based Policies towards Fast Execution

2026-11-08 · NeurIPS 2026 Robot Learning Workshop · RIKEN AIP / 东京大学

解决
不改训练，只在控制层面能把 ACT 的执行提多快；异步到达的新 chunk 和当前的运动对不上。
做法
控制线程把（不连续的）预测位置当参考，在加速度限制下做 tracking control，平滑地收敛到最新的 chunk；重叠预测的方差小，就一次走 2 步。
快在哪
ALOHA 上 box handover 16.2 s → 8.6 s（同步 → 异步 + CAC + 跳步，Table 2）；pen storage 成功率 30.0% → 83.3%（Table 1）。

PaperCode

Workshop 论文；控制频率和推理延迟没写。

#6Chronos Policy2026 下半年

Chronos Policy: Learning Robot Policies on Physical Time

2026-10-09 · arXiv · Stanford

解决
策略把感知和控制当成固定频率的序列，时间只靠“第几个”来表示；传感器频率或推理延迟一变就错。
做法
每个观测带上采集时刻，每个动作带上期望的执行时刻，用 time-aware RoPE 编码，注意力只看时间差。
快在哪
