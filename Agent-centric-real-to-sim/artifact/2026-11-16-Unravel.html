Unravel

Unravel: Recovering an Interactive 3D Scene from a Single Image

Hui Shan, Keyang Luo, Binjia Zhou, Ming Li, Kai Li, Xin Wang et al. · Zhejiang U、Shanghai Innovation Institute、Westlake U、LIGHTSPEED、Adobe、Fudan U、CityU HK、HKU · arXiv 2026-10-12 · 19 页

arXivPDFCode 仓库是 PDF 里给的，目前只有 README 和图，代码写着 coming soon；没有 project page

归档到 Agent-centric real-to-sim：一张室内照片 → 每件物体都能单独移动的 3D 场景，由 VLM 循环拆解、agent 最后 audit。

TL;DR

Problem
单张室内图 → 每件物体可单独移动的 3D 场景。One-shot 生成器一次猜完被挡的部分和位置，猜错了看不出、也改不了；交给 GPT-6 Astra 摆，位置也偏。
Idea
先拆后装。VLM 每轮挑出露全的物体，图像编辑器把它们移走、补出后面的内容，验证过才提交；物体在露得最全时建模。再按移除的倒序装回：点云给位置，观测跨度只当尺寸下限，最后 settling + audit。
Result
和同一套工具"只用原图"相比（5 个场景、160 个物体）：资产保真度 VLM 评分 4.7 → 8.2、人评 4.9 → 8.6，每场景点数 1.53M → 2.81M（Table 1）。和 MIDI、SAM 3D、GPT-6 Astra 只比了图，没有布局或物理指标。

Problem

被挡住的部分只能一次猜完：形状猜错，位置跟着错，而且没处检查

Running example · 后面每个 stage 都跟着它走

Fig. 1 / Fig. 2 / Fig. 8 的厨房：一张厨房照片，左边一台对开门冰箱，中间岛台配 3 个吧凳、台面上有碗和盘，头顶 2 盏吊灯，后墙一排上下柜、灶台和嵌在吊柜里的微波炉；岛台挡住了后排的地柜和灶台 → 想要：地面和墙组成的 shell，每件物体一个独立、带贴图、可移动的 mesh 和它的位姿、逐轴尺度，并记下谁放在谁上面。

怎么读这张图

  1. Input image 列：上面是书房，下面就是 running example 的厨房。
  2. MIDI 列：物体都生成了，但各自散开：厨房的吊柜东一块西一块，台面和电器对不上位置。
  3. SAM3D 列，红色虚线圈：厨房岛台后面那排地柜（原图里被岛台挡住）被做成一块浅浅的薄片，右下是放大；书房里桌上小盒和书架也变了形，灰框是同一结果换个视角。
  4. Unravel 列，绿色虚线圈：同一个地柜，有完整的深度和柜门，位置也对。这个地柜就是后面 Stage 2 在第 4 轮、露全时才建模的那件。

根本问题：形状补全和摆放绑在一次预测里，被挡部分猜错了，错误会传进布局，而且分不清、改不了（§1）；只靠语义推理的 agent 又说不清照片里的几何（§2.3）。　这篇的切入点：把补全挪到 2D 图像里一层层做，每层先验证再用；拆的过程记下每个点来自哪一轮、哪个像素，装回去时当几何依据。

Level 2 · Stages

6 个 stage：前 3 个每轮循环一次，第 4 个整理点云，后 2 个装回

怎么读这张图

  1. (a) 上排 Input / current image → Agentic loop（Plan → Edit → Verify，带回环）→ Intermediate round → … → Empty room：拆的循环，右上标 Removal order。对应 Stage 1–3。
  2. (a) 中排 Initially reconstructed point clouds → Per-round point cloud reconstruction, alignment, and fusion → Final fused point clouds：每轮重建、对齐到第一轮、融合。左下原图点云里白色的空洞就是被挡住、看不到的区域。对应 Stage 4。
  3. (a) 虚线框 Assets and spatial evidence：左边 Independent 3D assets（Extract before each removal），右边按物体着色的点云；中间 Instance correspondence 把资产和点簇一一对上，Instance labels 来自融合点云。对应 Stage 2 和 Stage 4。
  4. (b) 上排 Environment shell → Object retrieval and placement ① → Intermediate round → Interactive 3D scene ②：从空 shell 开始按 Reverse removal order 放回。对应 Stage 5。
  5. (b) ① One-sided registration：3D asset 加 Instance partial point clouds，求 s, R, t（尺度、旋转、平移）得到 Results；底下一行 Similarity fitting under one-sided extent constraints。对应 Stage 5。
  6. (b) ② Final audit：Physical settling 里 Grounding（Floating → Grounded）和 Penetration resolution（Interpenetrating → Separated），右边 Agentic refinement 是 Render → Inspect → Refine 的循环。对应 Stage 6。

Level 3 · Details

每个 stage 的细节

Stage 1 Plan：VLM 挑出露全的物体 当前图 → 红框（本轮移除）+ 绿框（保护）
  • Why：只有完整露出的物体才能拿到干净的快照；删错东西会把信息永久抹掉，所以拿不准的一律保护。
  • How：GPT-5.5 看当前图，把完全可见的物体标为移除目标（红框），其余标为保护（绿框），框画在一张 plan image 上。
  • 规则：墙和地面保留；先拿走里面或上面的东西，再拿装它们的容器（contents before containers）。
  • 定位（A.1）：一次调用给所有目标画框，每个编号一个框；两个框 IoU ≥ 0.85 视为同一物体画了两次，多的那个重测。
  • 每个全局框再单独局部采样一次核对：IoU ≥ 0.5 就确认；否则判为漂移，对这个目标局部采样 3 次，保留和别的样本 IoU ≥ 0.7 的，逐元素取中位数替换。
  • 画好红、绿框的 plan image 再给 VLM 看一次：还没框到的可移动物体一律加为保护。漏检的物体因此被保护，而不是被误删。

Running example 在这一步

厨房第 1 轮（Fig. 8，见 Stage 2）：红框是 冰箱、2 盏吊灯、微波炉、吐司机、搅拌机、岛台上的碗盘、3 个吧凳。岛台、灶台和所有柜子这一轮不动，分别等到第 2、3、4 轮：岛台上还放着碗盘，灶台被岛台挡住一部分（按上面两条规则推断，论文没逐件解释）。

Stage 2 露得最全时建模（best-observed snapshot） 本轮的图 + 目标框 → mesh + mask + 移除轮次
  • Why：直接从原图建模时，被挡的物体只有残缺的 mask，生成器只能猜，出来的是破网格、多余部件、编出来的内容（Fig. 6 上排，见 E2）。
  • How：每件物体在被移除之前的那一刻保存快照，这时它露得最全（它刚被判为"完全可见"）。
  • SAM 3 只在它的框里分割，得到 instance mask，比整图分割准。
  • gpt-image-2 把快照转成 canonical 图（论文没细说，应指单独、干净的物体图），TRELLIS.2 再生成带贴图的 mesh。
  • asset index 记下 mesh、mask、语义、框和移除轮次，留给 Stage 4 标注和 Stage 5 装配。

Stage 3 Edit + Verify：移走、补全，验过才提交 当前图 + plan → 验证过的下一张图 + edit mask
  • Why：被挡的内容在 2D 图像里补出来，中间结果看得见、能检查，错的编辑在进入重建之前就被拦下。
  • How：gpt-image-2 按 plan 删掉红框物体，补全腾出来的区域，得到下一张图。
  • VLM verifier（GPT-5.5）在提交前查三件事：漏删的目标、误删的物体、凭空编出的内容。
  • 通过才提交。前后两张图之间变化的像素就是这一轮的 edit mask，Stage 4 用它判断哪些点是新露出来的。
  • 循环回 Stage 1，直到只剩空房间。验证不通过时怎么重试（重编辑几次、要不要重新规划）论文没写。

Running example 在这一步

第 1 轮编辑后（Fig. 8 Round 1 下半）：冰箱位置变成一面空墙，吧凳和碗盘消失，岛台还在；这一轮的 edit mask 就是这些像素。之后岛台（第 2 轮）、灶台（第 3 轮）、全部柜子（第 4 轮），一共 4 轮到空房间。教室用了 6 轮（Fig. 4），消融的 5 个场景每个 4–8 轮（§4.3）。

Stage 4 点云对齐、融合、按层标注 各轮的图 → 融合点云、每件资产的点簇、shell
  • Why：每轮从不同的编辑图重建，不加控制尺度和位姿会漂（论文称这是 key challenge）；而且单视角点云里一个像素只能有一个标签，被挡在后面的表面无从归属。

ri物体 i 被移除的轮次吧凳 1，岛台 2，灶台 3，地柜 4

  • How · 对齐：相机内参各轮固定。用 anchors（Ak）解闭式相似变换（Umeyama），把第 k 轮的点对到第 1 轮；残差大的 anchor 多在编辑边界和阴影残留处，剔除后重解一次。
  • How · 融合：只加新信息。上一轮编辑过的像素（Ek−1）贡献它们新露出的表面，没编辑的像素保留原来的点。拆掉的物体的点也留着。
  • How · 标注：相机固定，一个像素就是一条光线，每轮在这条光线上看到不同深度。第 k 轮加进来的点叫第 k 层；第 k 层的点归给"mask 盖住这个像素、到第 k 轮还没被移除（ri ≥ k）"的物体里最靠前（最早被移除）的那个；一个都没有就归房间（0）。后面的移除不会改已有的标签。
  • 结果：每件资产一个点簇 Ci；房间的点拟合出 shell（地面和墙）。

  1. Per-round aligned reconstruction：每轮的图单独重建、对齐到第一轮。换个视角看，物体背后白色的空洞就是这张图里被挡住的区域；越往后物体越少，Round 5、6 只剩空房间。
  2. Cumulative fused point clouds：从 Original image 的重建开始累加。拆掉的物体的点一直留着，桌子下面、椅子后面的白洞一轮轮被新露出的表面补上，Round 6 时教室完整。

Stage 5 倒序装配 + 单侧注册（observed points = lower bound） shell + 资产 + 点簇 → 每件的位姿和逐轴尺度
  • Why：谁托着谁需要一个装配顺序；而生成的资产是完整的，点簇只有朝相机的那一面，硬把完整资产贴到部分点上会把它缩小。
  • How · 顺序：容器要等上面、里面的东西拿走才完全露出，所以"i 放在 j 上"必然有 ri < rj。从空 shell 开始按移除轮次从大到小装，每件到场时它的支撑物已经在了。

Stage 6 Physical settling + agentic audit 注册后的场景 → 不悬空、不穿插、查过错的场景
  • Why：注册只保证"放在看到的地方附近"，不保证物理上说得通：会悬空，也会插进邻居里。
  • How · 分类：由语义关系和局部支撑几何推出 support graph；挂画、吊灯这类挂在墙上或天花板上的是 mounted，固定不动；其余是 movable。

说明什么
资产更像，几何更多。保真度 VLM 4.7 → 8.2、人评 4.9 → 8.6；融合 4–8 轮后每场景点数 1.53M → 2.81M。第 1 轮之后才移除的物体，直接重建的 mask 平均只有 Unravel 的 77.2%（第 2 轮 85.0%，第 4 轮 60.4%），11.3% 不到 70%；全部物体里 5.6% 不到 50%，最低 23.8%。点簇覆盖：这些物体平均 76.9%，10.1% 不到 70%、3.8% 不到 50%，最低 11.9%。
在故事里
证明"露得最全时建模"和"逐轮融合"给了更好的输入；这是全文唯一一组数字。
指标
Area ratio = 直接重建的 mask 面积 ÷ Unravel 的 mask 面积（只算第 1 轮之后移除的物体，约占三分之一）；mask UCR = 比值低于 70% 的物体比例。保真度 1–10 分：1–3 形状错或缺关键部分，4–6 认得出但变形，7–8 形状对、有小瑕疵，9–10 形状结构都对、包括原图里被挡的部分。Points = 每场景平均点数；geometry UCR = Unravel 点簇被直接重建覆盖不到 70% 的物体比例。
怎么评测
  • 5 个场景、160 个物体；两边都用 SAM 3、TRELLIS.2、MoGe-3，direct reconstruction 只用原图。
  • GPT-5.5 和 15 名评审各自独立盲评：每件物体两个 mesh 从 4 个 90° 视角渲染，左右随机，对照同一张参照图。

Limits

局限和开放问题

  • 论文自述（§5）：受限于图像编辑模型；很乱的场景里，编辑可能改动剩下物体的外观或位置，这种漂移跨轮累积，破坏点云对齐和摆放；验证能减少但消除不了小错。展望是更强的编辑器加几何反馈，以及在小错累积前触发定点重试的不确定性检查。
  • 我的观察：摘要说"恢复更多物体、摆得更准、物理上更合理"，但全文没有一个布局或物理指标；和 MIDI、SAM 3D、Astra 只有定性图。
  • 我的观察：唯一的数字（Table 1）只和自己的 direct reconstruction 比，参照又是 Unravel 自己的 mask、点簇和裁图，评委之一是 pipeline 里同一个 GPT-5.5。
  • 我的观察：被挡表面来自编辑器补出来的图，是"验证过的猜测"，不是观测。"interactive" 指物体可单独移动、有支撑记录：没有质量、摩擦，没有关节（柜门、冰箱门打不开），没跑物理引擎，settling 是几何约束优化。
  • 我的观察：没报耗时、模型调用次数和成本；audit 和 Astra baseline 都走网页界面，代码仓库目前只有 README，复现难。

For Agent-centric real-to-sim

对我们有什么用

  • r2s-lite：pot-lid 那集靠宽松的成功规则在第 9 次过关、场景却是错的。Unravel 的门槛更窄：编辑提交前查三种具体的错；几何修正只在拟合不变差时保留；settling 只许物体朝观测点簇挪、不许远离。可以给修复环加一条"每次修复都不能让物体离 DROID 观测更远"的硬约束，而不是只看任务成功。
  • real2sim-anything-indoor：视频 → Blender 房间时，把生成资产对齐到局部点云这一步直接套用"看不全的轴只把观测跨度当下限"；放置按"谁托着谁"排序，再做最小位移 settling（3 cm 接触容差、不穿插、吊灯挂画不动）。被沙发、桌子挡住的后排物体，也可以先在关键帧上"移除再补全"再建模。
  • WorldClaw：Unravel 把"每件物体放在哪个表面上"存进场景，挪动或替换物体后能重新 settle。WorldClaw 的白盒场景可以存同样的 support graph，并在送进 Genesis 前跑一遍"渲染 → 检查 → 局部修 → 再 settle"；真正的物理检验仍要靠 Genesis，Unravel 本身没有物理引擎。
