Ego2Sim2Humanoid: Agentic Real-to-Sim for Learning Loco-Manipulation VLAs without Robot Demonstrations

归档到 Agent-centric real-to-sim：coding agent 把每条眼镜录像重建成可仿真的场景（碰撞和贴图资产、补全看不见的面、物体上的接触带），再转成 humanoid 的训练轨迹。它也贴近 Sim-robot-learning（人体动作 → humanoid、RL tracking、sim-to-real）。

TL;DR

Problem
眼镜录像只有 RGB-D、头部轨迹和视野里的手，没有身体。把人的动作照搬到身高、臂长、手型都不同的 G1 上，机器人走不到位，三指手也抓不住：EgoHumanoid 系列在 71 条帽子录像上找到的可行抓取是 0 条。
Idea
一个 coding agent 把每条录像重建成可仿真的场景：碰撞和贴图资产，补全看不见的面，在物体上标出 contact band。之后由固定的规划器和动作生成模型（Kimodo）按 G1 的身材和 Dex3 手重新做站位、抓取和全身动作。最后在物理仿真里用 agent 组合的 reward 做 RL 跟踪，只收下物体真被拿起、机器人没摔的 rollout，图像从机器人相机沿同一条 rollout 渲染。
Result
只用转换出的数据（零真机示范）微调 GR00T N1.7，G1 真机举瓶 9/20、戴帽 5/20（Fig. 6，没有真机 baseline）。在同一批 71 条帽子录像上，手到接触区的距离是 0.8 cm，可行帽檐抓取 57 条；EgoHumanoid 系列是 70.8–112.9 cm 和 0 条（Table II）。

眼镜只录下头和视野里的手：照搬到 G1 上，站不到位，三指手抓不住，也没人在物理里检查

Running example · 后面每个 stage 都跟着它走

一条戴帽子录像（hat wearing）：示范者只戴 Project Aria Gen 2 眼镜，走到桌边，拿起桌上的帽子，戴到头上。这类录像共 154 条，每个任务配一条语言指令。眼镜给出标定好的 RGB-D（双目深度）、重力对齐的 6-DoF 头部轨迹，以及手在视野内时的 3D 手部姿态和手指 landmark。躯干和腿没有记录。

→ 想要：29-DoF Unitree G1 + Dex3 三指手 能执行、在物理仿真里验证过的全身轨迹，加上沿同一条 rollout 渲染的机器人头部相机画面，组成训练数据去微调 GR00T N1.7 (3B)，全程不用真机示范。

论文的方法图（Fig. 2、Fig. 4）画的是另一项任务 bottle lift（走到桌边，右手抓瓶，举起），管线完全相同。这里跟帽子走，因为全部对比数字都在帽子录像上（Table I、II），而且它多一段视野外的动作：把帽子戴到头上。

"照搬人手掌"是论文自己的对照（Table I）：只换抓取，其余步骤和 RL 阶段都相同。两条 EgoHumanoid 的坏点来自 §IV-d 的分析：两者都照搬示范者的身体和手掌，没有场景和物体模型，走路误差和手位误差叠加。为了排除走路误差，论文把 baseline 机器人挪到示范者站的位置再解手指，仍是 0 个可行帽檐抓取（完整 V2 的手掌离人手掌 6 cm，解出的手指离接触带还差 2–6 cm）。两个 baseline 都用作者发布的代码跑。93.9 cm 是 V2 的 kinematic 版（71 条）；完整 V2 只跑完 6/8 条 held-out 录像，为 112.9 cm。

根本问题：眼镜录像没有身体，也没有场景和物体模型。照搬人的动作时，身高、臂长和三指手的差异让站位和接触同时出错，而且没有一步在物理里检查手能不能真把物体拿住。　这篇的切入点：先让 coding agent 把每条录像重建成可仿真的场景，并在物体上标出接触带；再对着重建规划机器人自己的站位和抓取，补出看不见的身体动作；最后在物理仿真里跑通才当作训练标签，图像也从机器人相机沿同一条 rollout 渲染。

Level 1 · Big picture

每条眼镜录像先变成 agent 重建的 twin，再在 twin 里改写成 G1 自己做得到的动作，最后从 G1 的相机重看一遍

怎么读这张图

  1. Egocentric Recordings（左）：示范者只戴 Aria Gen 2。小图是眼镜看到的画面：桌面、物体和自己的手。帽子录像也是这样录的：走过去，拿帽子，戴上。
  2. Target Contact Bands（左下）：两个圆柱上的橙色和青色区域是预测的接触带，即物体表面上手该落的那一段，存在物体自己的坐标系里。帽子的 band 在帽檐上。
  3. Agentic Real-To-Sim（中上，机器人和代码图标代表 coding agent）：从录像重建出的桌面场景，G1 已经放了进去。
  4. Whole-Body Adaptation & Correction（底部椭圆）：Grasp + Stance Planning → Whole-Body Motion Generation → Physics Alignment（Kinematic Refinement、RL Tracking、Semantic Rewards）→ Optimized Rollouts，对应下面的 Stage 2–4。
  5. Robot-View Learning（右）：从 G1 头部相机渲染的画面，里面是机器人自己的手臂。经 "Zero Target-Task Real Robot Data" 进 Whole-Body VLA。

5 个 stage（Fig. 2 底栏）；agent 只出现在重建和 reward 两处

怎么读这张图

  1. 左上 Bottle Mask / Human Hand Landmarks：agent 分出的物体 mask（青色）和眼镜跟踪的手部 landmark（橙色）。帽子录像里就是帽子的 mask 和手。
  2. Original Human Egocentric Video：原始的眼镜画面序列。
  3. 橙线 Human Camera Path (Aria) 和绿线 Robot Camera Path (Adapted)：机器人相机沿人的头部路径走，但降到机器人的高度，并随站位调整。
  4. 青色机器人 Human Hands Unseen：走近时手不在视野里，由 Kimodo 生成走路和手臂动作。Blend Before Visibility：手进视野之前就开始渐变。
  5. 蓝色机器人 Human Hands First Tracked：手进入视野，跟踪到的手部 landmark 接管手臂。
  6. 红色机器人 Table Clearance Needed / Shift Stance To Reach：直接站在投影的头部路径上会撞桌，所以要做 bilevel 站位优化。
  7. 灰色机器人 Kinematic And Physics Corrected In Sim：最终姿态 = 调整后的站位 + 按接触带规划的 Dex3 抓取，再经运动学优化和 RL 修正。
  8. 右上 Copied Palm → Planned Grasp：照搬人手掌造成穿透（红）和没碰到（橙）；规划的抓取全是接触（绿）。帽子上的同一对比就是 Table I。
  9. 下方 Textured Scene → Collision Scene，以及 Visual / Collision 两行：贴图场景配简化的碰撞几何；每个物体一个视觉网格加一个碰撞模型，青色是 Contact Region。第一列就是帽子。
  10. 底栏五格：Real-To-Sim → Motion Adaptation → Kinematic Correction → Dynamic Correction → Robot-View Data，就是下图的 5 个 stage。

Level 3 · Details

每个 stage 的细节

Stage 1 Agentic real-to-sim 眼镜录像 → 碰撞场景 + 贴图视觉网格 + 物体 6-DoF 轨迹 + 接触事件和接触带 + 物理参数（§III-A，App. A）
  • Why：录像里没有可仿真的场景和物体。不预扫实验室，不用 CAD 模板，每条录像现场重建。
  • 谁来做：一个 coding agent 跑分阶段的重建流程，每个阶段都对照原始帧检查，而不是一个固定脚本。用的是哪个模型、什么 prompt、跑了几轮，论文都没写。
  • 标定：设备标定把每帧的头部位姿映射到 RGB-D 相机，图像、双目深度和手都放进同一个重力对齐的公制世界坐标系。
  • 深度格式检查：agent 比较跨视角重投影残差、跟踪特征的一致性和裸地面的平整度，判断深度是沿光轴的 axial depth 还是沿光线的 radial range。
  • 碰撞场景：地面（z = 0）和支撑面（桌子、沙发）拟合成平面加边界（Eq. 8）。每个场景元素和物体建一个简化碰撞模型（box、convex parts 或 hinged links），保留支撑面高度和抓取尺寸。
  • 物体轨迹：逐帧调整物体的 6-DoF 位姿，让投影剪影盖住物体 mask、不压到背景，另加平滑项（Eq. 1）。手的像素不计入；物体被完全挡住的帧，跟着接触它的身体部位走。
  • 视觉网格：在每个物体自己的坐标系里融合 TSDF（去掉示范者和移动物体），多视角 mask 把融合出的面分成物体和支撑面两份，每个面从可见性最好、法线最正、深度一致的视角取贴图（Eq. 9–10）。视觉网格和碰撞模型挂在同一个局部坐标系上，一起动（Eq. 7）。
  • 补全（可选）：头戴相机只看得到正面，拿走物体又会露出下面的支撑面。紧凑物体拟合超椭球这类低参数形状；沙发这类支撑物加一层内缩的背板壳，颜色从附近的可见面插值。补出的视觉壳标为 inferred，和碰撞模型分开存。
  • 接触事件：reach onset（手臂开始伸出）、first touch（指尖进入它离物体最近距离的 1 cm 内）、full grasp closure、lift-off（物体离开触碰位姿超过 1 cm）、release。
  • 接触带：在抓合时刻附近，把物体表面的候选点投到各个标定视角，按离手 mask 的远近打分。审过的 seed 再扩成一段 band，比如横跨内外壁和边沿的扇区，或沿把手的一段弧，存在物体坐标系里。
  • 物理参数：质量、惯量和表面摩擦由 coding agent 凭先验从视频估计（§V）。没有辨识，取值也没有报告。
  1. Textured Scene → Collision Scene：左边是 TSDF 加贴图的视觉场景，右边是给物理用的简化几何：桌面是一块板，地面是平面，瓶子是小圆柱。
  2. Visual 行：五个物体的贴图网格：帽子、椅子、带红色细管的瓶子、两个圆柱杯罐。
  3. Collision 行和 Contact Region（青色）：同一物体的简化碰撞模型，青色是预测的接触带。帽子的青色块在帽檐和帽壁上，后面 grasp planner 就把手指放在这里。
  1. 第 1 格：一帧眼镜画面，客厅、沙发和抱枕。
  2. 第 2 格：重建在录像相机位姿处的渲染。
  3. 第 3 格：相机从 1.56 m 降到机器人相机高度 1.30 m；眼镜从没看到的面露成暗灰色。
  4. 第 4 格：抱枕被分离成独立物体，背面已补全；把它抬起 45 cm（直箭头）、转 20°（弯箭头），虚线是它原来在沙发上的位置，后面露出补全的沙发背板。

Running example 在这一步

帽子录像 → agent 先确认双目深度的格式，拟合地面和桌面平面；给桌子和帽子各建一个简化碰撞模型（保留桌面高度和帽子的抓取尺寸）；用剪影跟踪帽子从桌上到头上的 6-DoF 轨迹；在帽子自己的坐标系里融合 TSDF 并贴图，帽子网格和桌面网格分开，帽子被拿走后桌上不留副本。按 1 cm 规则定出 first touch 和 lift-off，再把手 mask 附近的表面点扩成帽檐上的一段 band（上图 Collision 行第一列的青色区）。帽子的质量和摩擦是 agent 估的。这条录像是否用了补全，论文没说；补全的效果见 Fig. 3。

Stage 2 Motion adaptation 头部路径 + 视野内的手 + 接触带 → G1 全身参考轨迹 x̂（骨盆位姿 + 关节角）和时间映射（§III-B，App. B）
  • Why：眼镜不记录身体；G1 的身高、臂长、三指 Dex3 手都和人不同，人的动作不能直接复制。
  • 目标（Eq. 2）：从机器人站立姿态出发，机器人相机跟住人头（平面位置、朝向、按身高比例缩放的高度变化），手可见时到达手目标，全程留在无碰撞、平衡、可执行的状态里。
  • 根参考：头的位置投到地面，水平视线方向用高斯核平滑，滤掉短暂的转头（Eq. 12）。人的脖子独立于躯干转动，所以不能把头的位姿直接平移给骨盆。
  • 头部误差只保留装在躯干上的相机能复现的部分：平面位置、朝向，以及乘上 ρ 的高度变化，ρ = 机器人与人站立时相机高度之比（Eq. 11）。
  • 手目标（Eq. 3）：可见段跟踪人手掌（映射到机器人手掌坐标系）；接触段改用 grasp planner 的结果，挂在物体坐标系上。
  • Rule-based grasp planner（Eq. 13）：在 MuJoCo 的 geom-to-geom signed distance 上做有界最小二乘，解手臂和 7-DoF Dex3 手指。规则：手宽沿 band 切向，掌心朝 band；边沿卡进拇指和食指之间的虎口，不深穿；食指和中指指垫贴 band 外侧，拇指贴对面的内侧；其余 link 不碰物体、支撑面和机器人自己；掌心居中；手掌和前臂朝向与人相差约 12°–15° 以内。从多个初值解，取指垫离 band ≤ 4 mm、没有 link 穿透超过 3 mm 的最低代价解。放在支撑面上的简单圆柱物体（比如瓶子）则沿物体轴滑动人手掌位姿，直到张开的 Dex3 离开支撑面。
  • Bilevel 站位（Eq. 4–5）：直接站在头部路径上可能够不着或撞桌。外层在 SE(2) 站位上网格搜索加局部梯度，要求离障碍至少 ds；内层用阻尼最小二乘 IK 解腰和手臂，"手到目标"的权重远大于"跟住头"（Wa ≫ Wv），并偏向站立姿态。
  • 时间重排（Eq. 14–15）：每段的时长取人的原时长和"路径长度 ÷ 机器人速度上限"中的较大者。
  • 全身动作（Eq. 16–17）：Kimodo（按约束生成动作的模型）以根路径点、可见手关键帧和站位关键帧为条件，分重叠窗口生成，窗口之间混合并衰减边界残差。
  1. Copied Palm（左）：黄线是人手 landmark 骨架，Dex3 照着它摆。红色 link 穿进物体（Penetration），橙色指头没碰到（Missed Contact），只有绿色那根是接触。
  2. Planned Grasp（右）：按接触带规划，两侧指垫都是绿色（Contact），没有穿透。
  3. 对应到帽子：帽壁只有几毫米厚，照搬时拇指或食指会直接扎穿；Table I 量的就是这个差别。

Stage 3 Kinematic correction 生成的全身参考 → 渐变后的手目标 + 运动学可行的轨迹 + 合手指令；kinematic physics replay 不过就丢弃（§III-C，App. C）
  • Why：Kimodo 只近似满足关键帧，视野外的手没有约束；手一进视野就切到跟踪手会有速度跳变；生成的动作还可能撞场景，或在合手前推动物体。
  • 渐变（Eq. 18）：每个可见段的前后各留 Tf = 0.6 s 的窗口，用 smoothstep 把生成的手位姿渐变到跟踪的目标；fade-in 恰好在手进入视野时结束。
  • 重新规划抓取：在生成的身体上重新解一次 grasp。
  • 轨迹优化（Eq. 19）：手到目标；贴近生成的动作（对应关节组的先验强度随渐变系数在两档之间插值）；支撑脚不滑；重心投影留在支撑多边形内；不碰撞；平滑。
  • 合手（Eq. 20）：从抓合到 lift-off，手腕固定在物体坐标系里；手指从张开插值到 closed 姿态，开合时机取自人手 landmark 的 pinch / curl 统计。
  • Kinematic physics replay：让手在 free-moving 的物体上合拢，检查合手前没有推动物体、合手后接触能持续。不过就整条丢弃，不把录像改到"刚好能过"。

说明什么
物理检查确实在筛，薄壁物体的产出很低。帽子只留下 59/154，瓶子留下 189/219。帽子的指垫落在 band 内的帽壁上，但帽壁只有几毫米厚；有的录像拇指在帽冠内没贴住帽壁，有的手在合手和 lift-off 之间漂了几毫米。replay 发现接触撑不住，就丢弃，不修改。
在故事里
说明 "physically verified" 有实际作用：过不了物理的录像不进训练集。
指标
一条录像要依次通过 motion adaptation、kinematic physics replay、physics rollout check 和最终 review，才算进训练集。
怎么评测
  • 示范者只戴 Aria Gen 2，不用机器人，也不用身体追踪器；每个任务配一条语言指令。
  • 每一关各掉了多少条没有分别报告，只说帽子"多数在仿真前"。
  • 几个帽子数字之间的关系论文没交代：E2、E3 用的 71 条 "checked" 录像怎么从 154 条里选出没说，进训练集的 59 条也多于 Table I 里规划抓取成功的 56 条和 Table II 的 57 个可行抓取。

E2按接触带规划抓取，比照搬人手掌好在哪？§IV-c

说明什么
穿透更浅，帽子在手里更稳，但成功数差不多。中位穿透 0.8 cm 对 1.8 cm，71 条里有 65 条是规划的更浅。在两边都成功的 43 条里，有 36 条是照搬的帽子在手里动得更多：手内位移 3.7 对 6.6 cm，旋转 22.9° 对 33.0°。论文报告这两项比较都是 Wilcoxon p < 0.001。RL rollout 成功数是 56 对 53（43 条两边都成功，23 条只有一边成功）；作者的结论是 planner 提升的是接触质量，不是成功数。
在故事里
支撑 Stage 2 的核心设计：对着接触带重新规划三指手的抓取，而不是照搬五指人手。
指标
穿透 = 合手到松手之间，任一手部 link 侵入帽子的最大深度，统计全部 71 条。手内位移和旋转 = 帽子在手坐标系里的最大平移和转动，从拿住到帽子到达头部，只统计成功的 rollout。报告中位数加四分位距。
怎么评测
  • 照搬组：手腕放在 retarget 过来的人手掌位姿，在录像的接触时刻合成固定手型；其余所有步骤不变。
  • 两种运动学参考里帽子都粘在合拢的手上，不会滑；手内运动只在 RL 带着接触物理跟踪时才出现。
  • 两组的接触点都落在预测的 band 内，因为示范者抓的正是 band 标出的帽檐。

E3同一批帽子录像，EgoHumanoid 系列能变成可行的机器人动作吗？§IV-d

说明什么
本文的机器人走得到、手到得了、抓得住；两个 baseline 一个可行抓取都没有。路径比 0.9 对 0.5 和 0.6；触碰时刻手到接触区 0.8 cm，EgoHumanoid 70.8 cm，V2 kinematic 93.9 cm，V2 full 112.9 cm；可行帽檐抓取 57/71 对 0。
在故事里
说明"照搬身体和手掌、没有场景和物体模型"的路线在 humanoid 上走不通，即使去掉走路误差也一样。
指标
Path = 机器人与人路径长度之比的中位数。Hand = 录像记录的触碰时刻，手到接触区的中位距离，在每个方法自己的 rollout 姿态上测。Grasps = 把 baseline 机器人挪到示范者站的位置后，能找到的可行帽檐抓取数。
怎么评测
  • baseline 用作者发布的代码跑：EgoHumanoid 和 EgoHumanoid-V2 kinematic 跑全部 71 条，完整 EgoHumanoid-V2（带动力学 refinement）只在它跑完的 6/8 条 held-out 录像上评测。
  • Grasps：固定各方法输出的手腕位姿，把 baseline 机器人挪到示范者站的位置，再解 EgoHumanoid-V2 机器人手的手指去勾帽檐且不穿透。
  • 推断：接触区就是本文自己预测的接触带，而本文的 planner 正是朝它优化的，所以 Hand 和 Grasps 两列天然偏向本文。

E4只用转换数据训的 VLA，在 G1 真机上能完成吗？§IV-e

说明什么
零真机示范也能完成整段 loco-manipulation，成功率中等，失败集中在抓取。举瓶 9/20（45%）：3 次没走到桌边，17 次走到；6 次把瓶子碰倒，2 次空中合手；抓到的 9 次全部举起。戴帽 5/20（25%）：20 次都走到桌边；10 次没抓住，2 次空中合手；抓到的 8 次里有 3 次在相机视野外戴帽时撞到机器人自己的头。
在故事里
全文的终点：转换出的数据本身就够训出能在真机上跑的全身 VLA。
指标
每个任务 20 次自主试验；瓶子被举起、帽子戴上算成功。
怎么评测
  • 29-DoF Unitree G1，Dex3 手，头部相机；GR00T N1.7 (3B) 只用转换数据微调（瓶子 189 条、帽子 59 条），动作由冻结的 SONIC decoder 解码。
  • 没有 baseline：既没有用遥操作数据训的 policy，也没有用 EgoHumanoid 数据训的 policy 做对照。
  • 真机在录像的同一场景里测（Fig. 4）；物体摆放和机器人起点怎么变化，论文没写。

Limits

局限和开放问题

  • 论文自认：质量、惯量、摩擦由 coding agent 凭先验从视频估计；重物或质量分布不均的负载会有 sim-to-real 动力学差距（§V）。
  • 论文自认：物体表示成刚体、参数形状或铰链 link，做不了叠衣服、切面包这类高度可变形或拓扑会变的任务（§V）。
  • Agent 不透明：没写用哪个 LLM，也没写 prompt、工具、轮数和花费；"逐阶段对照原始帧检查"没有量化，也没有拿掉 agent 的消融。
  • Twin 本身没验证：重建几何和接触带都没有和 ground truth 比；"physically verified" 是对着这个 twin 查的，筛选阈值也没报告。
  • 真机证据薄：两个任务各 20 次，没有 baseline，测试场景就是录像场景；戴帽失败里有 3 次是在视野外撞到自己的头，正是只靠语义 reward 指导的那一段。
  • 薄壁物体产出低：帽子 154 条只留下 59 条；几个帽子数字（71、57、56、59）之间的关系没有交代。
  • 渲染差距：渲染帧和真机相机的色彩平衡不同，眼镜没看到的区域也不同（Fig. 4 caption）。

For Agent-centric real-to-sim

对我们有什么用

  • r2s-lite（DROID episode → Isaac Sim twin，agent 带 repair loop）：pot-lid episode 在第 9 次尝试时靠宽松的成功规则过了，场景却是错的。E2S2H 的做法正相反：多道关串联（抓取 4 mm / 3 mm 验收 → 在 free-moving 物体上 replay，查"合手前不推、接触持续" → Λ 同时要求物体最终误差、头部跟踪和五项身体检查），不过就整条丢弃，不改到能过。成功规则里可以照搬"物体最终位姿误差 + 接触持续"。但它同样只对着自己的重建验证，场景错了也照样能过，pot-lid 那类问题它没有解决。
  • real2sim-anything-indoor（video → Blender 房间，GVHMR 人体动作）：可以直接借它的资产约定：视觉网格和碰撞模型挂在同一个物体局部坐标系（Eq. 7）；在物体坐标系里做 TSDF，用多视角 mask 切分，拿走物体不会在支撑面上留副本；补全（超椭球、沙发内缩背板壳）单独标成 inferred，不进碰撞模型。它也说明了没有身体轨迹时怎么办：头路径投地，再用 Kimodo 补视野外的身体，对应我们用 GVHMR 恢复的身体。
  • WorldClaw（prompt → white-box scene → Genesis）：reward 不让 LLM 随意写，而是从固定的 term library 里按任务语义和接触事件组合（Eq. 22–23），目标还可以挂在身体 link 的坐标系上（帽子相对头部）。WorldClaw 给 Genesis 场景定任务和成功条件时，可以用同样的受限组合，比自由生成代码更容易查错。
