SceneAgent

SceneAgent: An Agentic Pipeline from 3D and 4D Captures to Simulation Environments

Luke Hollis, Tianxing Fan, Heng Yang · Harvard Computational Robotics Group（SEAS） · CoRL 2026 Late Breaking Results（项目页 News） · arXiv 2026-10-26 · 27 页

arXivPDF Project page

归档到 Agent-centric real-to-sim：coding agent 带一套 skills，把 3DGS、扫描和视频转成 Isaac Lab 场景，并在仿真器里看图检查、修复，正是 agent 驱动的 real-to-sim。

代码未放出（项目页 Code 写 coming soon）。数字都来自 PDF；取自项目页的内容会注明“项目页”。

TL;DR

Problem
把一次采集转成可交互仿真，要串起分割、mesh 生成、对齐、物理估计等多个模型；单个模型输出看着合理，拼进场景后 mask、scale 或位姿一错，物体就不能用，而且没人检查。
Idea
把整条转换写成 coding agent 用的 skills（可复用的说明 + 工具，Fig. 7 里 21 个 agent 角色），每一步都在 Isaac Lab 里渲染、看图、修：每个物体看 overlay + 8 个单独视角 + 2 个场景视角，ICP 四项残差全过阈值才接受；视频则拟合仿真动力学，再和原视频并排对比。
Result
GraspClutter6D bin（20 个 YCB 物体）上 6 个 harness 的 F1@1cm 全部从 2.36–9.51% 升到 40.45–60.75%，SimFoundry 6.9%（Fig. 5）；4DCodeBench 三例上 Gemini 4 Argon 的 dynamic IoU 0.86% → 99.09%（Fig. 3）；代价是 token 成倍增加（Codex 10.0M → 271.2M，Fig. 6）。

Problem

单个模型都“看着对”，拼进场景后 mask、scale、位姿一错，物体就不能用

Running example 在这一步

bin 的 13 张 1920×1080 RGB 走 COLMAP + splatfacto。Antigravity 带 skills 时这一步（S1 Cameras and 3DGS）用了 6.9M token，不带时 1.8M；S0 Setup（skill discovery）带 skills 不到 0.1M（Fig. 6）。

Stage 2 物体：mask → Gaussian → mesh → 位姿 splat + 相机 → 每个物体一份对齐好的 mesh；背景补洞
  • Why：§3.1 的典型错误：mesh 形状对，插进场景后 scale、朝向或位置却错了；不同视图的 mask 是不是同一个物体也要判。
  • How ①：SAM 默认每 10 张输入图出一次 mask（各场景 stride 在 1–10）。
  • ② OpenCLIP ViT-B-16 给每个 mask 裁图一个 512 维向量，DINOv2 ViT-S/14 给每个物体一个视觉向量；两者只给 physics prior 用，不决定哪些 Gaussian 属于哪个物体。
  • ③ 跨视图合并 mask：两组 Gaussian 的中心相距不到 min(0.10, 0.6 × 物体尺寸) 个重建单位，且包含度 ≥ 0.18 或 Jaccard ≥ 0.08。
  • ④ Gaussian 归属（式 1，见下表）：中心投影落在 mask 里，且深度不超过“同一粗格子里最靠前的深度 + 容差”。物体的 Gaussian = 归入它所有 mask 的并集；可选 camera-consensus（至少 κ 个相机同意），实验用 κ = 1。
  • ⑤ SAM3D 生成 mesh；trimmed similarity ICP（只有一个统一缩放）以 SAM3D 位姿为初值，把 mesh 对齐到物体的 Gaussian。
  • ⑥ 接受门：normalized median 距离、90th-percentile 距离、coverage、silhouette agreement 四项都过固定阈值才接受（阈值数值未报告）。
  • ⑦ 拿走前景 Gaussian 后，用检测到的平面补背景：新 Gaussian 取附近平面在输入图里的颜色，可选 LaMa 纹理修补（06 Infill）。

式 (1) 的符号

符号白话值
πc(µi) ∈ mGaussian i 的中心投到相机 c 的图上，落在 mask m 里—
zc(µi)这个中心离相机 c 的深度—
ẑc(bi)同一个粗格子 bi 里最小的深度，即“前表面”；格子边长 round(s/192) 像素、最多 16，s 是图像短边—
ϵa绝对容差，以重建单位计0.08；厨房里约 7 cm（0.90–0.93 m/单位）
ϵr相对容差，乘以前表面深度0.03

读法：深度 ≤ 前表面深度 + max（绝对容差，相对容差 × 前表面深度），即只收前表面附近的 Gaussian，挡在后面的不收。

Running example 在这一步

Antigravity 带 skills：S2 2D masks 7.8M、S3 3D instances 5.8M、S5 Mesh generation 9.3M token；不带：3.0M、0、6.1M（Fig. 6）。没有 skills 时它根本没做 3D instance 分组（推断，依据那个 0）。论文没报告 agent 找到了几个物体、重试了几次。

Stage 3 物理、parts、关节，以及软体和断裂 每个物体 → 材料类别和质量、摩擦等先验；需要时拆 parts、补隐藏几何、加关节
  • Why：采集只给外观，质量、摩擦、关节都看不出来。作者明说不解逆物理，只给“物理上合理”的近似值，作为 domain randomization 的起点（§2）。
  • Physics prior：一个 MLP，输入 DINOv2 + OpenCLIP 特征 + 16 个几何量；输出头：材料类别（10 类）、body type（6 种）、碰撞形状（8 种），再回归 9 个数值属性（质量、密度取对数）。
  • 它的训练标签：GSO、YCB、ABO 的物体记录，标签由 VLM 写，不是实测。
  • 物体级：per-Gaussian 的类别 logits 和属性在物体的 Gaussian 上取平均；材料类别用加权投票（式 2）；之后 VLM audit 和自动的 material review（由 coding agent 签字，不是人）可以改掉它。
  • 查表：Young's modulus、Poisson's ratio、渲染材质按材料类别查；rigidity 是 0–1 的分数，deformability ≥ 0.65 的物体变成 soft body。
  • 进仿真的部分：Isaac Lab 导出只用质量、摩擦、restitution、body type、碰撞近似，其余存为 USD metadata。
  • Parts 和关节：PartSAM 拆部件 → VLM 查缺失几何（如笔帽下的笔尖）→ CubePart 生成缺的部分接到 mesh 上 → Articulate Anything 按图或文字提出 URDF 关节和运动范围 → agent 在仿真里看运动。
  • 软体和断裂：羊皮纸用 Warp 里的正交各向异性薄片 FEM + 不可逆 cohesive 断裂（49 个界面依次断开，撕下的纸盖住碗口 95%）；陶罐用 NVIDIA Blast（抗拉强度 6 MPa、杨氏模量 6 GPa、断裂能 14 J/m²、密度 1850 kg/m³，都是工程假设）；两者都不在自动导出里。

Stage ∞ Skills + 检查修复循环 贯穿 Stage 1–6：skills 告诉 agent 怎么做，Isaac Lab 的渲染告诉它做对没有
  • Skills 是什么（§1 原文定义）：harness 是 coding agent 运行的软件环境（Codex、Claude Code、Antigravity、Muse、Stirrup、Grok CLI 等）；skills 是“引导它转换流程的可复用说明和工具”（reusable instructions and tools）。
  • 有哪些：Fig. 7 的 21 个 agent 角色各配一个 skill，共 18 个名字（SCENEAGENT-RUN-PIPELINE、-INGEST-DATA、-RUN-STEP、-ALIGN-SCENE、-INSPECT-ISAAC……）。
  • 实验里的 “with skills”：同一个任务 prompt，只多一句让 agent 用 SceneAgent skills；所有 run 用同一版 skills，没有人干预（§4.1）。Fig. 6、4 的 S0 Setup 就是 skill discovery 这一步。
  • 没公开的：skill 的正文（代码 coming soon），所以每个 skill 写了哪些指令、带了哪些脚本，只能从 Fig. 7 的一句职责和 §3 的工具描述去推。

一次转换里的检查修复（§3.1）

  1. 规划：Orchestrator 从输入状态规划整条转换和处理步骤；每一步按 manifest 执行。
  2. 执行：Ingest agent 准备数据、建 3DGS；runner 跑处理工具，每一步做 “actor-critic visual review”（论文只给了这个词，没展开谁当 critic）。
  3. 逐物体审：reviewer 依次看 registration overlay → 8 个单独视角（6 个轴向 + 2 个斜向）→ 2 个物体在完整场景里的视角。
  4. 打回：发现对齐、关节或拆分问题，agent 提出修正的位姿或别的修法，再审一遍。
  5. 记账：接受或拒绝的输出记进 ledger；agent 之间通过场景目录里的文件传状态。
  6. 收尾：Alignment 和 Orientation 调物体 transform 和背景摆放；Packager 组装；Inspector 在 Isaac Lab 里审导出结果。
  7. 留下经验：每次转换的做法存成文件，后续转换可以读。论文强调，上面的修正只针对当前这次转换。

跨转换的 skill 自我改进（§3.1）

  • agent 维护 skills 和工具，被要求去调研能改进转换结果的方法；找到后申请评测，再改 skills。
  • 候选改动和当前 baseline 一起跑一组静态 3D、动态 4D、video-to-4D 基准；过了固定的改进阈值和回退阈值才保留。
  • 公开版的外部用户：通过的改动经用户同意变成 draft PR，作者再跑独立基准、人工 review 后才合并。
  • 未报告：ICP 四项和 skill 改动门限的数值、每个物体平均打回几轮、reviewer 用的是不是 harness 自己的模型。

Limits

局限和开放问题

  • 论文自己承认：转换要反复调 VLM，还要一台外部 GPU 工作站；细节多的环境慢且易错。
  • 视觉检查只能发现几何不一致，确认不了隐藏几何和物理参数是否准确；背景补全和变体都在“猜”采集里没有的内容。
  • 质量、摩擦、刚度、关节参数没有用机器人实测标定；断裂参数是工程估计；splat 带着原场景的光照，重打光和合成 mesh 会有不一致的阴影和反射。
  • 评测范围窄：重建只有一个厨房和一个 bin，每个配置一次；4D 只有 3 个合成场景，真实 4D 视频没有 3D 真值、未评；真机只有 pick-and-place；变体、摆放、光照一起随机，没有分开；缺真实与仿真的配对试验，评不了它对 policy 评测的预测力。
  • 4D 拟合出的参数能复现观测到的运动，但不一定唯一，也没在别的交互上测过（§3.6）。
  • 读的时候注意到：Fig. 3 里 GPT-6 Astra + SceneAgent 的点（约 0.78、约 60M）和正文 36.38%、Fig. 4 的 83.7M 对不上；厨房数据集的出处前后不一（§1 [8] 和 §4.1 [1]）。
  • Physics prior 的训练标签是 VLM 写的，material review 由 coding agent 签字；Fig. 9 的 corduroy 帽子，分区刚度标着 Hand-authored reinforcement（350–6,000 N/m，not measured）。
  • 门限数值、重试轮数都没报告；skills 本身没公开，“skills 带来多少”拆不成“说明”和“工具”各占多少。

For Agent-centric real-to-sim

对我们有什么用

  • r2s-lite：pot-lid 那次在第 9 次尝试时按宽松的成功规则过了，场景却是错的。SceneAgent 的接受条件是逐物体、多信号的：ICP 四项残差全过阈值，reviewer 还要看 overlay + 8 个单独视角 + 2 个场景视角，结果记进 accepted/rejected ledger。可以照搬成“每个物体一道门”，不只靠一条任务成功规则。
  • real2sim-anything-indoor（视频 → Blender 房间）：借 4D 的 clean-room rebuild：最终 build script 不许读输入视频，从零重建后再在早、中、晚帧和视频并排、叠加对比；既防 agent 直接拷帧，也给出可复现的产物。
  • WorldClaw skills：SceneAgent 把 skill 改动也放进一道门：候选改动和当前版本在静态 3D、4D、video-to-4D 基准上一起跑，过了改进和回退阈值才留。同时留意成本：bin 上 Codex 带 skills 用 271.2M token，不带 10.0M。
