TL;DR

Problem
单 agent harness 一个 conversation 跑完整个 episode：context 越来越长，模型还自己判自己成功。
Idea
parent 没有 set_gripper，只能调 grasp_engage(target)；harness 开一个零记忆的 child conversation 做一次 pick-and-place，结束后把 measured（harness 量的）和 claim（child 自称的）分开封装成 tool result 还给 parent。
Result
仿真抽屉任务：agent alone / agent parent 都是 4/5；MAS 中位 21 calls、0.43 M tokens（alone 19、0.38 M）。没变好，但每个 phase 的 context 都从头开始。

Stage 3 Engage + brief：分配 = 截住一个 tool call grasp_engage(target) → 封好的 brief + 一个 Child 对象
  • Why：没有调度器、没有并行：一次 grasp_engage = 一个 child，同步跑完才回到 parent。顺序由 parent 的 call 决定。
  • caps 截到剩余预算（episode.py:244）：每项取 min(phase 上限, episode 剩余)。剩不下 1 → budget_exhausted，不开 child。

  • child 的 layers：CHILD_LAYER + CHILD_SKILLS[--child-skill]（默认 place-into-container）。

贯穿 Context 管理：三层 phase 隔离 · 图片 prune · reasoning aging（context v2）
  • ① phase 隔离（MAS 自己的）：child 的 self.messages 是新列表；跨边界只有 brief（一行 target）和 result（measured + claim + 图）。child 的 17–28 个回合不进 parent 的历史。
  • ② 图片 prune（Episode.prune, agent.py:353；每个 session 各自一份）：attached 图超过 keep_images + 4 = 12 张，就把最旧的换成 [earlier image detached: steps/…]，只留 8 张。成批换，provider 的 prompt cache 前缀保持稳定。
  • ③ aging（context.age, context.py:36）：触发 = 图片要 prune，或距上次 ≥ 4 个 motion（CONTEXT_STRIDE），或上次 request ≥ 150k input tokens。动作 = 最近 6 个 assistant 回合以外的 reasoning_content 和 continuation 删掉，tool result 里的 observation body 换成 {observation_step, aged}；超水位只留 2 个回合。
  • ④ Static 字段（context.Static）：intrinsics、calibration、image_sizes 只在第一次观测给，之后写"as given at step N"。每个 session 一份 → child 第一次观测又会收到完整版。
  • ⑤ motion 一行摘要（context.summary）：每个 motion 结果开头一行 plain-language。
  • trace 不受影响：只改发出去的 messages；agent-events.jsonl 和 content-addressed 的 request/response 全保留。

KV cache：harness 不管 cache，只决定 request 的开头还是不是上一次的开头

  • 服务端没有 session：每次都是一个完整的 Chat Completions request（整个 messages + tools）。parent / child 只是 harness 里两个 Python 对象各自的 self.messages：发哪个列表，就是哪个 agent。
  • cache 是 provider 按前缀自动做的：开头和最近某个 request 一字不差的部分可以复用。harness 能影响的只有三件事：回复原样追加（带 continuation）；X-Session-ID（GPT-6 gateway 靠它把同一会话的 request 送到同一份 cache，model.py 注释："without which the gateway reused none of its prompt cache"）；prune 成批改旧消息。
  • parent 和 child 之间不共享 KV：system 之后的内容就不同了。双方都只能命中共同的固定前缀。
  • child 跑的时候，parent 的 messages 在内存里原封不动；parent 下一次 request = 上次的全部 + grasp_engage 的 tool result。服务端 cache 还在，就能命中。

Limits

局限和开放问题

  • child 只知道一行 target：parent 学到的教训（"竖直抓会在倾斜时滑"）只能塞进 240 字里；例子 phase 4 正是这样传的。
  • 5 分钟墙钟 cap 在例子里截断了 3/5 个 phase —— 这些 phase 白干，没有 claim。真机还要算 operator 审批的等待时间。
  • parent 的 prompt 也带 gripper-fit 层（RoleSurface 继承了 gripper_opening），虽然它没有 set_gripper。
  • child_instruction 把以句号结尾的 target 拼成 lid.. Limits（小瑕疵）。
  • 串行、单手臂：没有并行 child，也没有多种 child（ACHP 副本多了 gripper-only phase）。
  • --playbook、Isaac rig 还不支持（HARNESS_ONLY）。

For Robotic-harness

对我们有什么用

  • 这是 RoboDojo MAS（robot-harness-robodojo-mas 的 ScopedGraspPolicySession）的最小移植：契约复用 robot-harness-MAS 的 delegation_contracts，回合协议复用 Episode，新代码约 500 行（含 mas.py）。
  • measured / claim 分栏可以直接借给单 agent：给 finish_episode 也附一份 harness 量的事实。
  • 要让 MAS 胜过单 agent，最该改的是 brief：允许带上前几个 phase 的 result 摘要，而不只是 target。
